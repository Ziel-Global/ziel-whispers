### 1.2 Update AFTER Trigger — Capture `assigned_to_at_change`

Modify `public.record_task_status_history()` to write `NEW.assigned_to` into `assigned_to_at_change`:

```sql
CREATE OR REPLACE FUNCTION public.record_task_status_history()
RETURNS TRIGGER LANGUAGE plpgsql SECURITY DEFINER SET search_path TO 'public'
AS $$
DECLARE v_changed_by_type TEXT;
BEGIN
  IF TG_OP = 'UPDATE' AND OLD.status_id IS NOT DISTINCT FROM NEW.status_id THEN
    RETURN NEW;
  END IF;
  IF NEW.status_id IS NULL THEN
    RETURN NEW;
  END IF;
  BEGIN
    v_changed_by_type := NULLIF(current_setting('app.task_changed_by_type', true), '');
  EXCEPTION WHEN OTHERS THEN
    v_changed_by_type := NULL;
  END;
  IF v_changed_by_type IS NULL OR v_changed_by_type NOT IN ('admin', 'system', 'auto') THEN
    v_changed_by_type := 'system';
  END IF;
  INSERT INTO public.task_status_history
    (task_id, from_status_id, to_status_id, assigned_to_at_change, changed_by_type, changed_by)
  VALUES (
    NEW.id,
    CASE WHEN TG_OP = 'UPDATE' THEN OLD.status_id ELSE NULL END,
    NEW.status_id,
    NEW.assigned_to,                              -- NEW: capture who held the task
    v_changed_by_type,
    auth.uid()
  );
  RETURN NEW;
END;
$$;
```

### 1.3 Update `run_automation_rules()` — Template Scoping

Modify `public.run_automation_rules()` to:

1. Accept optional `p_workflow_template_id` parameter
2. Query rules matching either `project_id` OR `workflow_template_id`
3. Apply precedence: project-scoped rule always wins over template-scoped (regardless of `priority`)
4. Among same scope, `priority` decides; loser logged as `skipped`

```sql
CREATE OR REPLACE FUNCTION public.run_automation_rules(
  p_project_id UUID DEFAULT NULL,
  p_workflow_template_id UUID DEFAULT NULL,
  p_trigger_type TEXT,
  p_entity_type TEXT,
  p_entity_id UUID,
  p_root_event_id UUID DEFAULT NULL,
  p_depth INT DEFAULT 0
)
RETURNS void LANGUAGE plpgsql SECURITY DEFINER SET search_path TO 'public'
AS $$
DECLARE
  v_rule RECORD;
  v_run_id UUID;
  ...
BEGIN
  -- Fetch matching rules: project-scoped OR template-scoped
  FOR v_rule IN
    SELECT * FROM public.automation_rules
    WHERE status = 'enabled'
      AND trigger_type = p_trigger_type
      AND (
        (p_project_id IS NOT NULL AND project_id = p_project_id)
        OR
        (p_workflow_template_id IS NOT NULL AND workflow_template_id = p_workflow_template_id)
      )
    ORDER BY
      CASE WHEN project_id IS NOT NULL THEN 0 ELSE 1 END,  -- project scope first
      priority DESC
  LOOP
    -- ... rest of the execution logic (unchanged) ...
  END LOOP;
END;
$$;
```

Also update `run_scheduled_automations()` — template-scoped rules run once per active project using that template.

## Phase 2 — Category Mapping Fix ($7.5)

**Goal:** Every computation resolves status through `workflow_statuses.category`. No code reads the legacy `status` text column for decision logic.

**Scope:** ~30 lines across `ProjectDetail.tsx`, `LogSubmit.tsx`, `workflow.ts`, and one SQL migration.

### 2.1 Fix Strategy

The fix follows one consistent pattern everywhere:

| Pattern | Replace With |
|---------|-------------|
| `t.status === "complete"` | `doneStatusIds.has(t.status_id)` where `doneStatusIds = workflowStatuses.filter(s => s.category === 'done').map(s => s.id)` |
| `t.status === status.name` (kanban) | `t.status_id === status.id` |
| `s.name.toLowerCase() === "linked"` | find by `category === 'todo'` and `is_initial === true` |
| `TASK_STATUS_COLORS[t.status]` | `workflowStatuses.find(s => s.id === t.status_id)?.color` |
| Writing `status: "linked"` on task insert | Write `status_id: initialStatus.id` from the template's initial status |
| `update.status = "complete"` (hardcoded text) | `update.status_id = doneStatus.id` (looked up by category) |

## Phase 3 — Stage Outcome + Log-Triggered Transitions ($5.20)

**Goal:** Remove `updateTaskProgress()` auto-progress. Replace with explicit stage outcome declaration.

### 3.1 Backend

**A. Create `declare_stage_outcome` RPC**

```sql
CREATE OR REPLACE FUNCTION public.declare_stage_outcome(
  p_task_id UUID,
  p_to_status_id UUID,
  p_changed_by_type TEXT DEFAULT 'system'
)
RETURNS void LANGUAGE plpgsql SECURITY DEFINER SET search_path TO 'public'
AS $$
DECLARE
  v_current_status_id UUID;
  v_template_id UUID;
  v_valid BOOLEAN;
BEGIN
  SELECT t.status_id, p.workflow_template_id
  INTO v_current_status_id, v_template_id
  FROM public.tasks t
  JOIN public.projects p ON p.id = t.project_id
  WHERE t.id = p_task_id;

  SELECT EXISTS (
    SELECT 1 FROM public.workflow_transitions
    WHERE workflow_template_id = v_template_id
      AND from_status_id = v_current_status_id
      AND to_status_id = p_to_status_id
  ) INTO v_valid;

  IF NOT v_valid THEN
    RAISE EXCEPTION 'Invalid stage outcome: % -> % is not an allowed transition',
      v_current_status_id, p_to_status_id;
  END IF;

  PERFORM public.change_task_status(p_task_id, p_to_status_id, p_changed_by_type);
END;
$$;
```

## Phase 4 — Reassign to Stage Owner Action ($7.10)

**Goal:** New `reassign_to_stage_owner` automation action.

### 4.1 Backend

Add case to `run_automation_rules()`:

```sql
WHEN v_action_type = 'reassign_to_stage_owner' THEN
  -- Step 1: look for previous holder at this status
  SELECT assigned_to_at_change INTO v_previous_owner
  FROM public.task_status_history
  WHERE task_id = v_entity_id
    AND to_status_id = v_target_status_id
  ORDER BY changed_at DESC
  LIMIT 1;

  IF v_previous_owner IS NOT NULL THEN
    UPDATE public.tasks SET assigned_to = v_previous_owner WHERE id = v_entity_id;
  ELSIF v_fallback_role_id IS NOT NULL THEN
    -- Balanced workload across role members
    SELECT pm.user_id INTO v_chosen_user
    FROM public.project_members pm
    WHERE pm.role_id = v_fallback_role_id
    ORDER BY (
      SELECT COUNT(*) FROM public.tasks t2
      JOIN public.workflow_statuses ws2 ON ws2.id = t2.status_id
      WHERE t2.assigned_to = pm.user_id AND ws2.category != 'done'
    ) ASC, random()
    LIMIT 1;

    IF v_chosen_user IS NOT NULL THEN
      UPDATE public.tasks SET assigned_to = v_chosen_user WHERE id = v_entity_id;
    ELSE
      -- Log failure: no one holds this role
    END IF;
  END IF;
```
